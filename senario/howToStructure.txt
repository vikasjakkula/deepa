STEP 2: WHERE EACH OOP CONCEPT GOES
======================================================================
ENCAPSULATION  -> fields are private, read with getters, change stock only with setter
ABSTRACTION    -> parent class is abstract (generic product should not be created)
                  interface hides HOW the payable amount is calculated
INHERITANCE    -> 4 children extend the parent, constructor calls super(...)
POLYMORPHISM   -> Supplement s = new Vitamin(...); s.calculatePayable(3);
                  the child's method runs at runtime (overriding)
HAS-A          -> CartItem HAS-A Supplement, OrderCart HAS-A list of CartItems,
                  Store HAS-A list of Supplements
INTERFACE      -> parent implements Billable, children override its method
Object class   -> toString(), equals(), hashCode(), clone()

======================================================================
STEP 3: NAMING RULES
======================================================================
Class      -> PascalCase noun          Supplement, OrderCart, CartItem
Field      -> camelCase noun           supplementId, pricePerUnit, availableUnits
Method     -> camelCase verb           calculatePayable(), addToCart(), searchById()
boolean    -> is / has                 isGlutenFree(), isCaffeineFree()
getter     -> get + FieldName          getSupplementName()
setter     -> set + FieldName          setAvailableUnits(int units)
Interface  -> adjective (-able)        Billable, Sellable
Constant   -> UPPER_CASE               MAX_STOCK

INPUT / OUTPUT parameters:
calculatePayable(int quantity)  -> input: quantity    output: double (final amount)
searchById(int id)              -> input: id          output: Supplement (or null)
addToCart(Supplement s, int qty)-> input: item, qty   output: boolean (added or rejected)
getTotalValue()                 -> input: nothing     output: double

class Main

interface Billable
    double calculatePayable(int quantity);

abstract class Supplement implements Billable, Cloneable
    private int supplementId;
    private String supplementName;
    private double pricePerUnit;
    private int availableUnits;
    private String brandName;

    Supplement(5 params)
    getters for all 5
    void setAvailableUnits(int units)
    abstract double getDiscountPercent();
    double getStockValue()                     -> price * units
    double getSubtotal(int quantity)           -> price * quantity
    void displayDetails()                      -> prints common fields
    public String toString()
    public boolean equals(Object obj)          -> same supplementId
    public int hashCode()
    protected Object clone()

class ProteinPowder extends Supplement        (flavour, weightInKg)       10%
class Vitamin extends Supplement              (vitaminType, tabletsPerBottle) 5%
class EnergyBar extends Supplement            (calories, glutenFree)      8%
class HerbalTea extends Supplement            (herbName, caffeineFree)    15%
    each child has:
    constructor(5 parent params + 2 own params) -> super(...) first line
    double getDiscountPercent()
    public double calculatePayable(int quantity)  -> subtotal - discount
    void displayDetails()                          -> super.displayDetails() + own 2 fields

class CartItem                                 HAS-A Supplement
    Supplement supplement;
    int quantity;
    double getSubtotal()
    double getDiscountAmount()
    double getFinalAmount()                    -> supplement.calculatePayable(quantity)

class OrderCart                                HAS-A List<CartItem>

    void displayCart()
    int getTotalQuantity()
    void printBill()

class SupplementStore                          HAS-A List<Supplement>
    List<Supplement> supplements

    void displayAll()
    int getTotalTypes()
    int getTotalStock()
    double getTotalValue()
    Supplement searchById(int id)

======================================================================
STEP 8: VIVA - pick-a-number questions (answer in one line each)
======================================================================
1.  Why is the parent abstract?          -> a generic Supplement should not be created.
2.  Why private fields?                  -> encapsulation; stock changes only through setter.
3.  Why super(...) first line?           -> parent part of object is built first.
4.  Overloading vs overriding?           -> same name diff params (compile time) /
                                            same signature in child (runtime).
5.  Where is runtime polymorphism?       -> Supplement s = new Vitamin(); s.calculatePayable().
6.  Why an interface?                    -> a contract: every Billable must calculate payable.
7.  Abstract class vs interface?         -> abstract can have fields + constructors;
                                            interface only declares behaviour, multiple allowed.
8.  Why override equals?                 -> default compares addresses; we compare IDs.
9.  Why hashCode with equals?            -> equal objects must give the same hash (HashMap/HashSet).
10. What does toString do?               -> readable print instead of ClassName@hashcode.
11. Shallow vs deep copy?                -> shallow copies references; deep copies inner objects too.
12. Why is shallow clone enough here?    -> fields are primitives and Strings (immutable).
13. Why CartItem class?                  -> stock and ordered quantity must stay separate.
14. Why reduce stock in confirmOrder?    -> rejected / unconfirmed orders must not change stock.
15. Has-a vs is-a?                       -> CartItem has-a Supplement / Vitamin is-a Supplement.
16. Why ArrayList not array?             -> size grows; add/remove easily.
17. What if child does not override abstract method? -> child must be abstract, else compile error.
18. Can we create object of abstract class? -> No, only through child.
19. What is upcasting / downcasting?     -> child to parent reference (auto) /
                                            parent back to child ((Vitamin) s).
20. What is final?                       -> final variable cannot change, final method cannot be
                                            overridden, final class cannot be extended.
