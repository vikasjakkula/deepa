JAVA OOP ASSESSMENT
ShopZone – Level 1: Simple
Problem Statement
Develop a Java application named ShopZone for managing products, basic inventory, shopping-cart operations, billing, and product-specific behavior.
The application sells Electronics, Grocery, Clothing, and Medicine. Products share common information, but different products may have different discounts, taxes, delivery charges, and return periods.
1. Common Product Information
Every product must contain:
•
Product ID
•
Product Name
•
Brand
•
Retail Price
•
Available Quantity
Create a common product type for storing these details.
Product ID must be supplied when the product is created.
Product ID should not be changed after creation.
A generic product without a category should not be directly created.
2. Common Product Operations
Every concrete product should provide the following operations:
displayProductDetails()
calculateDiscount()
calculateTax()
calculateDeliveryCharge()
getReturnPeriod()
getDescription()
getPostPurchaseMessage()
The same method should produce different results depending on the actual product.
Example:
Product product = laptop;
product.calculateDiscount();
The caller should not need to determine whether the product is a Laptop, Milk, or Shirt.

23. Important Design Requirements
•
A generic Product should not be directly created.
•
Product ID should remain unchanged.
•
Common operations should be declared in the common Product type.
•
Concrete products should provide their own behavior.
•
Product references should support runtime polymorphism.
•
Products from different categories should be stored in one Product[].
•
ShoppingCart should support overloaded addProduct() methods.
•
Product-specific calculations should not be duplicated unnecessarily.
24. Final Objective
Show that Java OOP concepts can be used to build a simple online shopping system in which different products share common behavior while performing product-specific operations.
